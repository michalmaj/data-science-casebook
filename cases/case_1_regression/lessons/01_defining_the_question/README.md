# Lesson 1 — Defining the Question

**Estimated time:** 25-35 min

## Why we're doing this

TransLine's ops manager said only: "shipments are late, fix it." That's not a question we can answer with data yet. Before you touch a model, you need to turn that complaint into something specific and testable — and take a first, critical look at the data you've been given.

One thing from the same meeting: whatever we build has to work the moment a shipment leaves the depot, not based on information found out later (e.g. the weather it actually drove through). Keep that in mind already.

Today's question: given the shipment data TransLine has recorded, what exactly should we predict — and can we trust the data enough to start?

## How this lesson works

This is the first lesson, so a quick note on how every lesson here is built — it stays the same for the next seven.

- **You only edit `task.py`.** Three functions, each with a `TODO` docstring describing what it should do: `load_shipments`, `target_column_name`, `missing_value_counts`. Nothing else in this lesson needs changes.
- **You don't touch `check.py`.** It's a `pytest` suite that checks your functions. From this lesson's folder, run `uv run pytest` — `5 passed` means all three functions behave as described; any `FAILED` names which function and why (read the error message, it usually says exactly what the test expected).
- **`solution.py` is a lifeline, not a first step.** It holds the reference implementation. Open it once you're genuinely stuck after your own attempt — not before. The point of the exercise is reaching it yourself.
- **`lesson.ipynb` is where you run your code and write the interpretation.** Open the notebook *after* `task.py` passes its tests — that's where you'll see the data, generate the first statistics, and record your conclusions in the "Your notes" cell.
- **The lesson is done when:** `uv run pytest` reports `5 passed`, and `lesson.ipynb`'s notes cell is filled in with which columns look trustworthy and what you'd ask the client.

## What to watch for

Two columns have missing values. What to do about them depends on which column it is — there's no single universal rule ("drop the row" or "fill with the mean") that applies to every column, or every case. Lesson 2 handles this concretely; for now, just notice the gaps and start thinking about what each one means.
